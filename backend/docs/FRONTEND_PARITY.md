## 已补齐的差异

- 制度/风险：审批路径读取和保存、真实审批人校验、逐级通过、驳回、重送、修订后重新审核。审批结果和操作人由服务器决定；编制人员不能通过提交 status 绕过审核。
- 权责：跨任务审批历史查询，支持手册、事项、角色、操作人、动作、关键字及时间排序，返回前端筛选元数据。
- 流程：发布时保留自定义审批级次，逐级审核后发布；编制人可送审和撤回，只有审批权限可直接发布。定时发布配置持久化，每5秒检查到期流程，使用事务及版本唯一约束避免重复发布。修改待定时发布的流程会取消定时发布并恢复草稿。
- 架构：拖动、调整归属、集成图读取/保存；使用现有事务持久化和树循环校验。
- 组织：业务角色新增、修改、删除、菜单/功能/字段权限配置持久化。业务角色配置与系统访问角色仍然分离，参见 README 的授权边界。
- 接口目录：补上按 ID 更新接口；保留本地调试白名单及禁止生产数据演示重置规则。
- 模型：配置增改删、默认模型、真实连接测试；默认模型实际用于 AI 请求。外部模型采用 OpenAI 兼容 chat/completions 协议；未配置默认模型时沿用 GEMINI 环境配置。密钥 AES-256-GCM 加密保存，不回传客户端；只允许部署者指定的 HTTPS 主机，禁止重定向。
- 部署前端：同步 frontend/src 中落后的审批、表单、组织、发布和历史组件；制度/风险查阅仅显示显式 approved 条目，驳回或无审核状态的记录不进入已发布目录。

新增业务配置沿用现有 app_settings 的 dictBundle JSONB，无需修改历史迁移。历史手册与审批任务数据保持原结构。

## 运行配置与验收边界

1. 保存外部模型密钥前，为 MODEL_CONFIG_KEY 配置固定的32字节随机密钥（Base64编码）并备份。更换它将使原模型密钥无法解密。通过 AI_ALLOWED_HOSTS 配置允许访问的精确 HTTPS 主机，默认 api.openai.com 和 api.deepseek.com。已在 compose.yml 传入这两个变量。
2. 配置审批路径时使用实际启用用户。不会导入前端演示人名作为生产账号。旧制度/风险条目若没有 approved 状态，需正常送审后才能进入查阅目录。
3. 时间字符串应包含时区偏移，例如 2026-11-10T15:00:00+08:00。无偏移字符串按 API 容器时区解释。
4. ERP/CRM 外部抽取仍需真实系统连接器与凭据；现有接口返回503，不伪造抽取成功。流程执行仍为任务步骤清单，尚非完整 BPMN 并行网关引擎。多租户、部门行级保密权限及生产容量边界仍按 README 说明。
5. 本次没有使用真实 AI 密钥、ERP/CRM 或生产许可证进行外部验收，也未进行逐页面浏览器验收或生产负载测试。不能把接口覆盖数或编译通过表述为全部产品功能已通过生产验收。
6. 修改为源码交付；运行中部署需用审阅后的源码重新构建升级。未覆盖业务数据库或自动替换线上容器。
