# R2 P0 修复

## 当前指派人无法审批

统一审批中心按持久化审批路径的当前节点授权，不再要求被指派人额外拥有全局 auditor 角色。相同规则用于详情的 canAct 和实际处理；非当前节点、仅抄送人员、重复或过期记录仍拒绝处理。稳定用户 ID 优先，非唯一的历史显示名不授予权限。既有直接业务审核接口保留原角色校验，统一入口在事务中校验节点和 revision 后调用业务处理器。未为任何账号增加角色或更改流程责任人。

## 403 提示与菜单权限

登录和会话返回用户或启用的组织角色所配置的菜单权限；菜单权限只缩小可见范围，不能授予 API 权限。组织权限、系统设置仅对真实 admin API 角色显示；流程建设和制度/风险管理要求 editor。缺省菜单不再开放管理页面，all 或“超级管理员”显示标签不能突破 API 角色上限。跨模块导航也执行相同检查。

同源 /api/ 的 403 统一显示服务端 info，缺失或非 JSON 时显示中文兜底；拒绝继续执行成功回调。全局提示在模块 catch 之后显示，避免被“网络请求异常”覆盖。403 不注销会话。画布自动保存事件仅标记本地更改；只有服务器保存成功才标记已保存，失败返回时保留画布。

- viewer/editor/admin 的菜单范围、all 权限的上限、空菜单授权，以及启用组织角色的会话同步。
