# API 迁移核对

## 来源及覆盖范围

原型有 133 个 `app.get/post/put/delete('/api/...')` 注册；组件目录有 160 个 fetch 调用，包含重复调用及动态 URL。原始位置和表达式保存在 [routes.json](routes.json) 与 [frontend-requests.json](frontend-requests.json)。运行服务不读取原型文件。

迁移保留业务聚合的字段、中文状态、筛选条件及响应包装。原型控制器内的业务规则抽取到 [operations.ts](../src/domain/operations.ts)，由 Nest 服务在请求独立状态中执行，经过前置校验、事务持久化和统一错误处理。修正和补充逻辑位于 [extensions.ts](../src/domain/extensions.ts)、[validation.ts](../src/domain/validation.ts)、[domain.service.ts](../src/domain/domain.service.ts) 与 [native.service.ts](../src/native.service.ts)。这是兼容层迁移，不是把 Express 原型作为子服务继续运行。

## 已发现并处理的契约差异

| 前端行为 / 原型问题 | 迁移行为 |
| --- | --- |
| `PUT /api/flow/model` 不存在 | 新增流程名称/编号更新 |
| 删除架构和流程的接口不存在 | 新增两种 DELETE，拒绝删除仍被引用的对象 |
| `POST /api/flow/reorder` 不存在 | 新增排序，并持久化顺序 |
| `GET /api/flow/models` 不存在 | 与模型列表兼容的别名 |
| 前端调用角色 `batch-import`，原型只有 `import` | 同时支持两种路径 |
| 前端调用 `POST .../assign-users` 且传 `assignedUsers`，原型使用 PUT/users | 两种方法和字段均兼容 |
| `reset-presets` 路径不存在 | 保留明确响应：生产环境返回 409 |
| API 目录只有 GET，前端还有新增、编辑、删除、调试 | 补齐元数据 CRUD 和只读白名单调试 |
| 目录 `rename/delete` 返回成功但不执行 | 实现目录更新、非空检查和删除 |
| 不存在的流程返回列表第一项 | 返回 404，不再编辑/下载错误对象 |
| 全局用户共享、密码不校验、固定 token | 独立服务端会话、密码哈希、注销与撤销 |
| 前端网络异常时自动显示登录成功 | 移除绕过；HTTP 401 清理登录标记 |
| 发布时间和历史为固定示例 | 真实发布者、时间与不可重复版本快照 |
| 用户密码明文进入返回和数据对象 | 凭据独立表，响应递归脱敏 |
| 执行步骤固定为“起草/主管初审” | 从已发布流程 XML 的活动节点生成 |
| 不完成步骤也能提交办结 | 状态检查，未完成返回 409 |
| 日志导入忽略内容，返回随机数量 | 真实 CSV/JSON 解析、去重、事件统计 |
| “PDF 下载”实际返回拼接文本 | 正式文件缺失返回 404；有文件则返回真实字节 |
| 任意字符串可激活、伪造 RSA 验证结果 | 验签、机器标识及有效期校验；签发离线进行 |
| AI 失败后伪装成大模型结果 | 生成服务失败返回 503；规则/统计能力明确标识来源 |

## 安全及兼容性差异

1. 生产路由全部需要登录，登录和健康检查除外；原前端同源 fetch 自动携带 Cookie，无需给 160 个请求单独添加 Bearer 头。
2. 密码至少 12 个字符。`roleNames` 是业务角色，授权使用独立 `accessRoles`，不允许普通用户通过业务角色名称提升权限。
3. 演示重置端点有明确的 409 响应；“全部发布”仍保留原型 `itemIds: []` 的含义，且仅审批角色/管理员能执行。
4. `status=0` 配合 HTTP 4xx/5xx。原型中不存在记录仍返回成功、无效批量项被忽略等情况改为校验错误；整个事务回滚。
5. 已送审流程不能直接修改；已发布流程的编辑使工作副本变为草稿，发布快照保留。已归档手册只读。
6. 权责审批仍以现有姓名字段兼容前端；送审校验审批人是真实启用用户。正式使用应避免同名歧义，并逐步迁移前端审批人字段到用户 ID。
7. 动态 XML 仅校验语法、拒绝 DTD/ENTITY；任务执行支持未压缩的 Draw.io UserObject 活动。前端 iframe/富文本渲染的完整内容安全审查不包含在后端迁移中。

## 数据迁移

初始数据库为空，bootstrap 只建立管理员、根架构及表单模板。没有将原型中的示例用户、许可证、公司名、任务和历史审批灌入生产库。真实历史数据应通过经过核对的导入或专用迁移导入；没有自动导入原型的全局数组。

业务表采用一实体一行 JSONB 聚合，关系外键覆盖稳定的核心关联。手册内分类/事项、审批链和字段布局仍是嵌套数据；完整实体第三范式拆表、SQL 级业务分页和更细粒度并发锁属于后续容量优化，不在当前兼容实现中假装已经完成。
