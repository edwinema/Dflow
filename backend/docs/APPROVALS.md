# 统一审批中心

页面 `/approval/pending`、`processed`、`mine`、`cc`、`query` 分别提供待我审批、我已审批、我的申请、抄送我的、审批查询。旧业务审核页面与接口保留兼容；中心调用相同业务处理逻辑，不另建审批数据副本。

- GET `/api/approvals?view=pending&type=all&status=all&keyword=&page=1`：服务端按当前账号筛选，固定每页20条；计数仅来自可访问事项。
- GET `/api/approvals/:type/:id`：审批说明、步骤、历史及当前可用动作。
- POST `/api/approvals/:type/:id/action`：`action` 为 approve/reject/withdraw，携带 `revision` 和 `opinion`；驳回和撤回必须填写原因。
- 类型 flow/duty/sysDoc/risk 分别对应流程发布、权责事项、制度和风险条款。

仅申请人、审批路径参与人、实际历史处理人、明确的 ccUserIds 接收人和系统管理员可查询详情。只有当前受理且具有 auditor 权限的用户或管理员可审批；只有流程申请人或管理员可撤回流程申请。业务不支持的撤回不显示操作。普通用户的审批查询只查询本人相关记录，管理员可查全量。审批版本指纹会在写事务内重新比较，防止过期页面重复处理。

新申请持久化申请人ID，旧数据仅兼容已存在的账号名及唯一的显示名，不根据职位或业务负责人猜测申请人。历史申请缺少身份信息时不冒认归属，管理员仍可查询。抄送页面仅展示明确记录的接收人，不生成演示抄送记录。现阶段不包含抄送已读回执及统一审批模板编辑功能。

验证：隔离数据库覆盖四类业务、多人多级审批、我的申请/历史/抄送/查询隔离、拒绝越权、过期版本、重复审批、撤回及底层业务状态持久化。
